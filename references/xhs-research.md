# 小红书调研工作流（OpenCLI）

## 定位

小红书用于补充近期体验、氛围、拍照、排队变化和软性提醒，不替代景区官网、交通官网、高德 POI 或大众点评的硬信息。

环境、登录和真实搜索探针必须先按 `environment-setup.md` 通过。未登录、出现验证码或 Browser Bridge 失联时停止小红书调研，不把普通网页搜索结果标成“小红书已核验”。

## 首选：OpenCLI 内置适配器

先看当前注册表和命令帮助，不把旧版本参数当成事实：

```powershell
opencli list
opencli xiaohongshu --help
```

围绕“城市 + 具体地点/店名 + 决策问题”搜索：

```powershell
opencli xiaohongshu search "成都 文殊院 附近 早餐" --limit 10 -f json
opencli xiaohongshu search "成都 某餐厅 排队" --limit 10 -f json
```

第一轮只看前 10–20 条，判断是否真的在说目标地点。再用当前版本提供的 `note` 或详情命令精读最相关的 2–3 条；以 `--help` 显示的语法为准。

## 搜索与筛选

### 保留

- 明确店名、景点名、地址、菜品或具体入口；
- 作者自己的近期体验；
- 多条独立笔记重复出现的排队、预约、闭馆、动线或踩雷信号；
- 能改变选择或时间安排的信息。

### 丢弃

- 泛城市合集里顺手带一句；
- 搬运、广告口吻或无可核对细节的内容；
- 纯情绪描述和重复的“氛围很好”；
- 与目标城市、分店或日期不一致的笔记。

不要按点赞量直接排序决定可信度。记录笔记发布日期、实际体验日期（若有）和访问日期，避免把旧信息当成当前状态。

## 决策写回

每个候选只保留一层结论：

```md
地点：
- 代表笔记：链接
- 小红书信号：2–3 句，说明近期体验、排队/氛围/拍照/软提醒
- 可信度：高/中/低；理由
- 与路线的关系：顺路 / 轻微绕行 / 不建议为它改路线
```

不复制长段笔记原文。餐厅最终判断仍要结合大众点评、位置、预算和当天路线；营业时间、票务和闭馆日回到官方来源核验。

## CDP 诊断备用

只有在 OpenCLI 已通过 Stage 2、但某条详情读取因适配器页面变化失败时，才用同一登录浏览器的 CDP 做只读诊断：

1. 用独立调试配置启动 Chromium，并设置远程调试端口；
2. 直接导航到 `https://www.xiaohongshu.com/search_result?keyword=<encoded>`，不要模拟双层输入框；
3. 在真实页面会话中观察 `POST /api/sns/web/v1/search/notes`；
4. 详情页只提取标题、正文、作者和当前 URL；
5. 不复用、导出或记录 Cookie、签名参数和账号凭据。

若页面返回登录墙、`AUTH_REQUIRED`、风控或账号切换错误，让用户在同一浏览器中处理后重试。不要绕过平台验证，也不要直接伪造签名调用接口。
